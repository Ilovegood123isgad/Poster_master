# 快速开始

[English](en/getting-started.md) · [文档索引](README.md)

## 一次完整走查

假设老板说：**"下周要发骑行社团的招新海报，尺寸 A3，报名链接是 https://example.com/join，
主视觉用我发的那张夜骑照片。"**

### 第 0 步：把技能装上

见 [安装](installation.md)。装好后技能目录里应该有 <code>SKILL.md</code>。

### 第 1 步：让 Agent 选路由

```text
$poster-master 帮我做一张骑行社团招新海报。尺寸 A3，报名链接 https://example.com/join，
主视觉用 assets/夜骑.jpg，报名截止 10 月 26 日。
```

Agent 读 <code>SKILL.md</code> → 读 <code>workflows/routing.md</code> → 判定路由为
**新建海报**（若你说"别问了直接出稿"，走 Quick 档，跳过确认往返）。

### 第 2 步：回答真正影响设计的问题

Agent 只问会改变设计的问题，其余用假设推进并标注出来。典型问题：

| 问题 | 为什么必须问 |
|---|---|
| 投放在哪里？校内电子屏、打印展架、公众号推文？ | 决定尺寸、出血、色彩模式、文件格式 |
| 观看距离大概多少？一米内还是三米外？ | 决定字号层级，主标题可能差三倍 |
| 报名的最低信息是什么？时间、地点、名额、装备？ | 决定信息卡里放哪几行 |
| 二维码是最终链接吗？有没有短链或带参数链接？ | 二维码必须按确认链接重生成 |
| 图片和字体是谁的？能不能商用 / 印刷授权？ | 授权状态未知的素材不进交付物 |

已确认的内容用**事实**标注，推测的内容用**假设**标注，两者不混写。

### 第 3 步：拿到阶段产物

Agent 会在项目目录里写出六份阶段文档（模板见技能包 <code>templates/</code>）：

```text
我的项目/
├─ 01-需求简报.md
├─ 02-文案层级表.md
├─ 02-待确认问题.md
├─ 03-创意方向.md
├─ 04-初稿说明.md
├─ 05-反馈记录.md
├─ 06-交付检查表.md
├─ 素材台账.md
├─ assets/                     素材
├─ exports/                    交付物
└─ 项目名-组件源稿.poster.json  可继续编辑的源稿
```

### 第 4 步：出稿与迭代

初稿以**实际尺寸可读**为准，不是缩略图好看为准。改稿时，Agent 用
**修改海报**路由重进对应阶段，并把决定写进 <code>05-反馈记录.md</code>，
而不是重新生成一张图。

### 第 5 步：交付

Agent 跑交付检查并把结果贴给你：

```bash
python "<技能目录>/scripts/check_delivery.py" --project "<项目目录>"
```

报告里会明确区分**已验证**（尺寸、色彩模式、文件可读、二维码可解码）、
**需要人工确认**（实际距离可读性、文案事实、真机扫码、字体与图片授权）。

## 自己动手的两条命令

```bash
# 1. 建项目骨架
node "<技能目录>/scripts/new_project.js" --project "<项目目录>" --name "项目名" --size 1080x1440

# 2. 开编辑器（改元素、导出 PNG / SVG / PSD）
node "<技能目录>/scripts/editor/server.js" --project "<项目目录>" --port 41735
```

## 没有浏览器也能出图

```bash
python "<技能目录>/scripts/render_preview.py" \
  --source "<项目目录>/项目名-组件源稿.poster.json" \
  --output "<项目目录>/exports/预览.png"
```
