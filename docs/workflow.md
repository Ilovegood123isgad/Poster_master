# 工作流

[English](en/workflow.md) · [文档索引](README.md)

## 强制加载顺序

技能被触发后，Agent 必须按这个顺序读文件，不能跳：

1. <code>SKILL.md</code> —— 全局纪律、输入清单、六阶段、交付红线。
2. <code>workflows/routing.md</code> —— 路由判定。
3. 选定的那一条路由 —— 只有这一条的过程文件。
4. 该路由明确触发时才读的支持文档。

**不读第二条路由的过程文件。** 支持文档是细化，不是竞争。

## 路由判定

| 你要做的事 | 路由 | 过程文件 |
|---|---|---|
| 从需求或素材开始做一张新海报 | 新建海报 | <code>workflows/new-poster.md</code> |
| 同上，但不想被反复确认 | 新建海报（Quick 档） | 同上 + Quick 说明 |
| 改已有海报或源稿的内容、配色、尺寸 | 修改海报 | <code>workflows/revise-poster.md</code> |
| 在编辑器里逐元素精修 | 编辑器精修 | <code>workflows/editor-refine.md</code> |
| 换尺寸、出多版本、跑交付检查 | 导出交付 | <code>workflows/deliver.md</code> |

路由是确定性的：需求已经能判定时，不要再反问用户"你想走哪条路"。

## 六阶段

每条路由都是同一套六阶段的一个循环。**阶段属于海报，不属于路由**——
改稿时从拥有这个改动的那个阶段重新进入，而不是从头再来。

### 阶段 1 目标

**冻结**：受众、主要效果、核心信息、成功标准。

**门禁**：简报被接受；主要效果只有一个。
"高端大气上档次"不是效果，"让路过的人在 3 米外看清时间地点"才是。

### 阶段 2 信息

**冻结**：带优先级标签的文案集（P0 必读 / P1 次要 / P2 补充）、待确认问题清单。

**门禁**：每个 P0 事实已确认，或被明确挂起并写进交付说明。
文案没确认时可以先排版，但占位文案必须标出来，交付门保持关闭。

### 阶段 3 方向

**冻结**：3–5 个视觉关键词、配色、字体、主视觉、参考来源。

**门禁**：方向适配真实载体与受众。
方向单是决策清单，不是形容词集合。

### 阶段 4 初稿

**冻结**：至少一张可读构图 + 意图说明。

**门禁**：在实际尺寸下可读；层级经得起远看。
缩略图好看不算数。

### 阶段 5 迭代

**冻结**：版本化反馈记录，每条反馈都有决定。

**门禁**：事实复核过；遗留问题关闭或列入交付清单。

### 阶段 6 交付

**冻结**：按渠道分开的 PNG / SVG / PSD + 交付检查结果。

**门禁**：检查通过；没有任何一项是"假定已验证"。

## 门禁与阻塞

每个 ⛔ BLOCKING 门禁处，Agent 必须**停下等确认**，不替用户做决定。

典型阻塞点：

- 需求简报提交给客户后等待确认。
- 文案里 P0 事实缺失且无法用合理假设补齐。
- 二维码链接与客户提供的不一致。
- 素材授权状态不明。
- 交付检查未通过。

非阻塞步骤可以连续执行，不必每一步都问一次。

## 状态报告规范

每次汇报必须区分三类信息：

| 类别 | 含义 |
|---|---|
| **已验证** | 有文件、有版本、有检查结果、有日期 |
| **已设计** | Agent 的设计决策，可以被改 |
| **假设** | 暂定值，等确认 |

不要把草稿说成已定稿，不要把稿图说成终稿，不要把没实测的二维码说成可用。
